# Item models

The game's item models (`web/public/assets/models/<family>/<id>.glb`) are generated by Rust: a family's module
builds its models on the kernel, `artkit`, and `cargo art` writes their files, their pack entries and their
centres, then runs the gate. This is the guide for people and agents making or changing a model. The standard a
model meets (sizes, budgets, finishes, moving parts, what to look at) is
[docs/design/objects.md](../../docs/design/objects.md); the content fields are
[docs/content-packs.md](../../docs/content-packs.md); the gate and the other commands are
[tools/art/README.md](../../tools/art/README.md).

## What is where

| Crate | What it is |
|---|---|
| `crates/artkit` | The kernel: shapes, forms, parts, clips, the kit, botany, shading, the `.glb` writer ([src/lib.rs](../artkit/src/lib.rs) lists the modules). Its doc comments are the last word on a call (`rg 'pub fn\|macro_rules!' crates/artkit/src`) |
| `crates/art` (`ll-art`) | `cargo art` ([src/lib.rs](src/lib.rs)): the registry, the runner, `--check`, `--preview`; [src/template.rs](src/template.rs), the family to copy |
| `crates/art/<group>` | The families, six crates so they build side by side |
| `crates/tools` (`ll-tools`) | `cargo check-glb` (the gate) and the pack and centres writer (`src/art.rs`) |

| Crate (folder) | Families (`cargo art <name>`) |
|---|---|
| `art-nature` (`nature`) | trees, plants, garden_things, garden_decor, ground, street |
| `art-wet` (`wet`) | kitchen, kitchen_cooking, kitchen_counters, bathroom, laundry |
| `art-rooms` (`rooms`) | living, dining, office, decor, lighting, bedroom, bedroom_storage, bedroom_dressing |
| `art-packs` (`packs`) | pack_bookworm, pack_cheerful, pack_couchPotato, pack_energetic, pack_example, pack_foodie, pack_gloomy, pack_hotHeaded, pack_kind, pack_lazy, pack_loner, pack_natureLover, pack_neat, pack_outgoing, pack_romantic, pack_slob |
| `art-outside` (`outside`) | yard, outdoor, playground, farm, street_furniture, stalls, shops, civic, civic_works |
| `art-things` (`things`) | hobbies, kids, held, tabletop, media, fitness, birds |

A family is a folder, `crates/art/<group>/src/<family>/` (snake case: `pack_couch_potato` for `pack_couchPotato`):

| File | Holds |
|---|---|
| `mod.rs` | The palette, the family's constants, and `pub fn family() -> Option<Family>`: every model with its facts |
| `common.rs` | The family's own helpers |
| `<group>.rs` | The builds, a file a group of models (`chairs.rs`, `tables.rs`), a `pub fn <model>() -> Vec<Obj>` each |
| `NOTES.md` | What the models are, the facts they keep, the faults found |

`crates/art/rooms/src/dining`, `crates/art/wet/src/kitchen_counters` and `crates/art/nature/src/trees` are good ones
to read first.

## The loop

1. **Read** this page and the family closest to what you're making, then objects.md's sections for what you touch.
2. **Find the facts the game already has.** For an object that exists, its content entry
   (`grep -rn '"id": "<id>"' web/public/content`) and its model (`web/public/assets/models/<family>/<id>.glb`), whose
   size and heights it keeps. For a new object, decide the footprint first: it fixes where the game puts
   residents (below).
3. **Build and look.** `cargo art <family> --only <id> --preview`, then open the PNGs in
   `tools/art/previews/<family>/` (you can read images); `--sheet` for every side and each clip along its length.
   Iterate until it looks right from the front and each clip looks right open.
4. **Write it.** `cargo art <family>` writes the files, the pack and centres.json, and runs the gate on what it
   wrote. It must say `0 failed`; read every warning. Then `cargo check-glb --validate <key>` (the Khronos
   validator). A model that is right to fail a strict check takes `.accept("<check>", "<why>")` on its `Model`
   (tools/art/README.md, "The gate").
5. **Wire it in** when the object is new (below), and run `cargo test -p sim-core --test sim shipped_content::`
   (`cargo test -p sim-core` if you touched the sim).
6. **Look in the game.** The inspector and the gallery, then your own dev server driven headless (below): WebGPU and
   `&renderer=webgl`, at rest and with each clip playing, by day and at night. Judge it at the play camera
   (`check.mjs gallery --camera game`), where a player sees it; objects.md, "What reads at the play camera", says
   what shows there and what does not.
7. **Finish up.** `cargo art <family> --check` (the same bytes again), `cargo review sizes --check` and
   `cargo review uses --check`; the model's line in `NOTES.md` and in `web/public/assets/CREDITS.md`. A build gives
   the same bytes every time, so `git status` shows only what you changed; never commit `tools/art/previews/`.

Done means: the gate passes, the validator is clean, the tests pass, and you've seen it right in the game. Report
what you checked, and anything you didn't.

## Commands

```sh
cargo art kitchen                       # build, write the files, the pack and centres.json, run the gate
cargo art kitchen --only fridge,freezer # some models (the pack keeps the others' entries)
cargo art kitchen --preview [--sheet]   # pictures only, in tools/art/previews/kitchen/ (below)
cargo art kitchen --out /tmp/art/k      # write under another root, laid out as the repo is; no gate
cargo art kitchen --check               # build in memory, fail on any byte unlike the committed files
cargo art --all --check                 # every family (CI's `art` step, about 10 s on twelve cores)
cargo art kitchen --no-pack             # write the files, not the pack
cargo art --centres                     # centres.json from every family's models, nothing built
cargo art template --preview            # the template family (src/template.rs)
cargo check-glb model.fridge            # the gate on the files in the tree
cargo check-glb --validate              # every model, with the Khronos validator (`bun install` in web/ once)
cargo check-glb --keys                  # the keys a build may write
```

Each model prints its measured size, its triangles and what was written; a model that fails its size check prints
the measured size and centre to copy. `--preview` builds in memory and draws each model from its file as the game
reads it: `<id>.png` (the front three-quarter), `<id>@<clip>.png` (each clip where it is most open),
`<id>.far.png`, `<id>@perches.png` and `.top`; `--sheet` adds `<id>.sheet.png` (four sides and the baked
shading, then a row a clip at 0, 25, 50, 75 and 100 %). The pictures draw faces from the front only, as the game
does: one built inside out shows as a hole. The lit, textured view is the game's: `bun run dev` in `web/`, then
`/inspect.html?key=model.<id>` (from any side, with its footprint, clips and gate report, rebuilt each time
`cargo art` writes it) and `/gallery.html?keys=model.<id>`.

`tools/art/centres.json` holds each model's `centre` (key → `[x, depth]`; `[0, 0]`, the middle, for most): where
`settle` centred it, so the gate can tell a file that is off it (a stale build, a part moved). The game doesn't
read it. A build writes its models' lines; `--centres` writes every family's (after changing a `centre` without
a rebuild, or adding or removing models). A key it doesn't list isn't built here, and its centre isn't checked.
Commit it with the models.

**Never build in place in a shared worktree.** `cargo art <family>` without `--out`, `--check` or `--preview`
rewrites the models, the pack and centres.json in the tree.

## Coordinates, cheat sheet

| | Game (content, `GameFrame`) | The kernel (`cube!`, `sweep!`, the clips) |
|---|---|---|
| Axes | x right, y up, z towards the front | x left, y towards the back, z up |
| A point | (x, height, depth) | (−x, −depth, height) |
| Front | +z | −y |
| Origin | middle of the footprint, on the floor | the same: `settle_all()` puts it there |

- **Game numbers.** `GameFrame::new(shift)` takes game numbers as they are
  (`fbox!(F, name, w, h, d, (x, y, z), M.colour)`, `F.at(x, y, z)` for a point); use it to copy content heights.
  `shift` moves every depth forward (+z; a negative one back), to draw a thing built against the back of its tile
  centred on it. A clip's axis and offset, a `sweep`'s `up` and a bare `cube!`'s `at` are the kernel's.
- **Footprint.** `[w, d]` in whole 1 m tiles, before turning. A 2 × 3 object runs from −1 to +1 across and −1.5 to
  +1.5 deep.
- **Against a wall.** Its back is on the wall's face, 7 cm into the tile: at depth −0.43 in a 1-deep footprint,
  −1.43 in a 3-deep one. Built on the tile's edge, it sits inside the wall.
- **Residents** stand on the tile in front of the footprint to use it.
  - Sitting and lying, they are moved to the footprint's middle (slots spread across the width), or to each slot's
    own place and facing (content `places`: a picnic table's two benches). Build the seats where the places are.
  - Lying, the head is about 0.84 m behind that middle and the feet 0.86 m in front, whatever the footprint.
  - A bed's mattress is wherever its footprint's middle is. Its height is the renderer's `beds` table in
    `web/src/render/shared/characters/furniture.json` (default 0.5 m), not the model's.

## A new family

1. **The folder.** Copy [src/template.rs](src/template.rs) (a toy chest with a lid and a drawer: a palette, a
   `GameFrame`, parts joined, a hinge, settle, two clips, a `Model` with `motions` and `paint`) to
   `crates/art/<group>/src/<family>/mod.rs`; split the builds into files of their own as it grows. Rename the
   family and its models; `cargo art template --preview` shows what it builds.
2. **Register it.** `pub mod <family>;` and a row `("<family>", <family>::family())` in `families()` in the group's
   `src/lib.rs`; `family()` returns `Some(Family::new(..))`. The name is the models' folder
   (`models/<family>/`), the default key prefix (`model.<family>.<id>`) and the pack's folder
   (`.pack("<name>")` for another).
3. **The content.** Each model's key must be one a content object or item names, or one a manifest has, or the
   build refuses it before building anything (a misspelt key); a model the game draws by code takes `.code()`.
   Add the content entries first (below, "Wiring a new object into the game").
4. **The pack.** `cargo art <family>` writes `web/public/assets/packs/<pack>/manifest.json` and lists it in the
   base manifest's `packs`. Never edit a pack by hand: the build writes the whole entry (a pack entry keeps the
   `vary` of the entry it overrides and copies its other fields). The family's comment is the pack's `$comment`:
   say what the family is and that `crates/art/<group>/src/<family>` builds it.
5. **Build**: `cargo art <family>`, then the loop above.

## A new object

1. **Palette.** One material per colour, named for what it is, with its finish:

   ```rust
   palette! { M:
       body = ("#F3F3F1", gloss),                        // a comment says what wears it
       handle = ("#D0D3D6", chrome),
       glass = ("#DCE6EA", gloss, mirror(Mirror::Front)), // mirror glass, reflecting to the front
       shade = ("#F2E6CC", fabric, glow("#FFD9A0")),     // glows at night
       marble = ("#EDEAE4", gloss, roughness(0.28)),
   }
   ```
   - The names are the material names in the file; the finishes become the pack's `materials`.
   - The finishes are the base manifest's `material.finish.*`: matte, satin, gloss, enamel, ceramic, plastic and
     rubber, and the metals metal, chrome, brushed and iron (plain); fabric, velvet, leather, wood, lacquer, bark and
     foliage (textured: one more draw call each); leafcards (a tree's leaf cards, cut out of their atlas:
     `botany`'s `clad` puts them there) and glass. objects.md says what each is for.
   - Name the main part the player may colour `body`; list it first in `paint`, then any other parts worth
     colouring, each with what the player calls it. Leave details (drains, water, food) out.
   - Hardware (handles, knobs, pulls, latches, taps) takes a `metal` or `chrome` colour (objects.md, "Hardware is
     metal").
   - Mirror glass takes the side it reflects to (`mirror(Mirror::Front)`): a flat piece, on the still body or one
     moving part, `gloss`, never see-through `glass`.
   - A lamp's shade or a screen that glows at night takes its glow's colour (`glow(..)`; `screen()` for a screen).
     Nothing glows by day.
   - A plain finish may shine more or less (`roughness(x)`, `metallic(x)`): it goes in the pack entry and the game
     keeps it per vertex, so it costs no draw call.
   - A model whose colours differ from the family's takes its own: `.palette(M.palette().recoloured(&[("oak",
     "#8A6446")]))`, or `.palette(M.palette().with(&[Mat::new("oak", "#3A3C40", "iron")]))`.
   - Textured finishes get UVs made for each part as it is joined (`uv`): a box along its own longest sides (wood's
     grain runs along a leg, a rail, a table's length), round about its own axis for cylinders, cones, lathes and
     level-ringed lofts, along its path for a sweep (bark up a branch). A part built level and turned with `rot`
     turns its grain with it.
2. **Build** in a `pub fn <model>() -> Vec<Obj>`, in metres, from the shapes (`cube!`, `sphere!`, `cylinder!`,
   `cone!`, `torus!`, `rod!`, `revolve!`, `boulder!`; sizes are full extents, `bevel` rounds edges; the
   `GameFrame`'s `fbox!`, `fcyl!`, `fcone!`, `fsphere!`) and the forms, which make what boxes can't:
   - `sweep!` (`fsweep!`): a round tube or any `profile` along a path, curved through the points (`resolution`),
     tapering (`scale`): frames and rails in one piece, rolled arms, handles, branches;
   - `loft!` through `ring!`s (ellipses to rounded squares): bottles, vases, lamp bases;
   - `extrude!` (`fextrude!`): an outline with `holes` into a slab: a carved apron, a headboard, a grille;
     `forms::rounded_rect` and `smooth_outline` draw outlines;
   - `soft_box!` (`soft!`): cushions, pillows, mattresses, duvets (below, "Soft things");
   - `forms::mirrored`, `forms::bisect` (a cut along a plane), `jitter!` (a hand-made wobble);
   - `artkit::kit`: whole parts more than one family uses (`kit::tube!`, `fillet!`, `pull!`, `knob!`, `shaker!`,
     `moulding!`, `cabriole!`, `scroll!`, `bench_end!`, `songbird!`, `letters!`, `cut!`, `recessed_box!`:
     [kit/mod.rs](../artkit/src/kit/mod.rs) has an example of each); `artkit::botany` for plants and trees.

   The options are each builder's struct (`shapes::Cube`, `Round`; `forms::Sweep`, `Loft`, `Extrude`;
   `soft::SoftBox`), set by name in the macro: `fbox!(F, "top", 1.2, 0.03, 0.8, (0, 0.735, 0), M.oak, bevel =
   0.004)`; a misspelt option does not compile. A helper of the family's own is a plain function with every
   parameter. A part two families would make belongs in the kit: ask the kernel's keeper, do not copy it (a stopgap
   copy is marked `// KIT: <what it stands in for>`).

   **Soft things.** `soft_box!` is a box with what stuffing and seams do to one, each a few centimetres at most and
   none of it past the box, so the size you give is the size it has:
   - `puff`: its faces crowned (a number: the two across its thin side; three: each pair's own);
   - `pinch`: its corners pulled in and thinned where the seams meet, on by default (0.6 of the puff). The corners
     are then inside the box: give `pinch = 0.0` to one turned so that a corner is the model's outermost or highest
     point, and to what isn't stuffed (a mattress, a heap of washing);
   - `waist`: its sides drawn in between corners that stand out as ears (a pillow sewn flat);
   - `sag`: a seat cushion's top sinking over its front third, where the legs go; the sitter's hips stay;
   - `overhang`: its sides drawn in between its seams, the top standing over the boxing;
   - `tufts = (across, along)`, `tuft` (how deep), `diamond`, `button` (a material: a covered button in each dent);
   - `rumple`, `rumple_size`, `seed`: bedding, its top sunk in soft folds, its sides in flutes to a square hem
     (`calm`: smooth where a runner lies across it);
   - `piping`: a cord along the seams, reaching as far out as its radius;
   - `resting = true`: it lies on its underside or leans on its back: a third fewer triangles; give it to every
     cushion, mattress and cover that lies on something.

   Its steps (`flat`, `round_segments`) keep its rounded edges within 1.5 mm of their curve; give them only to
   save triangles on something small. A cushion a clip sinks is its own part.

   **Round things** take as many sides as keep their outline within a millimetre of the circle when the build gives
   no count (`shapes::sides`): a lathe 24 up to 12 cm in radius and more above (64 at most), a swept tube 12 up to
   3 cm, `kit::tube!` 8 up to 13 mm. A count the build gives is kept: `cargo review facets` lists what shows its
   flat sides.

   Spend the triangles where they show (silhouettes, edges, what a hand touches) and keep hidden parts plain. End
   with `join_all("<id>")` for a model with no moving parts, or one `join` per part (below), then `settle_all()`,
   which stands it on the floor, centred, by moving it, never scaling. A model that stands off the middle of its
   footprint is built in place, settled with `settle!(centre = false)` and given `.centre(x, depth)`.
3. **Declare it** in the family's list:

   | On `Model::new(id, build, (w, h, d))` | Does |
   |---|---|
   | `(w, h, d)` | The real size in game metres, checked after the build within `.tolerance(..)` (2 % a side if not said; a number, or one a side). Take it from the content, or from the measured line once the model is right. Never stretched |
   | `.key("model.x")` | The key, when it isn't `model.<family>.<id>` |
   | `.motions(json!({..}))` | When its clips play (below); a value worked out goes in brackets: `{"hold": (HOLD * 2.0)}` |
   | `.paint(&[("body", "Body")])` | The parts the player may colour, the main one first |
   | `.centre(x, depth)` | Where it stands off its footprint's middle (written to centres.json) |
   | `.on_wall()` | A thing on a wall: built at its real height, not stood on the floor |
   | `.far_low()`, `.far(build)`, `.far_ratio(0.25)` | Its far version (below) |
   | `.habitat("tree")`, `.bird(json!(..))` | Perches (below); a bird the game flies by code (crates/art/things/src/birds) |
   | `.sink(0.05)`, `.draws(5)`, `.ground(false)`, `.code()` | Sunk that far into the ground; more draw calls allowed; not shaded by the floor; drawn by code, its key in no content |
   | `.accept("footprint", "why")` | A strict check it is right to fail, with the reason |
   | `.palette(..)` | Colours of its own |

   - **Far versions** (`<id>.far.glb`, drawn where the model is only seen from afar: the town overview, the far
     woods, the street on Low): for what is placed by the hundred or seen far off (trees, hedges, street props, the
     farm's buildings). `.far_low()` runs the model's own build again at low detail: the build asks
     `far::low(full, reduced)` for each count, segment number or bevel and `far::is_low()` for what a far version
     leaves out (a flower's centre; moving parts, joined into one still part). It must draw every random number
     the full build draws, so its parts stand where the model's do. Better than decimating small, separate parts
     (flowers, leaves, twine), which turns them into spikes. `.far_ratio(0.25)` decimates the model at rest to that
     share of its triangles, keeping what stands within 1 cm of the floor or 3 mm of its box; `.far(build)` builds
     one by hand. The gate fails a far version whose lowest point is over 0.5 cm off the model's.
   - **Perches** (trees, shrubs, hedges): where the game's birds sit, the entry's `perches`. The build finds them
     on its own meshes (`perch::around`, lines in from outside; `perch::find` where they meet the leaves, then
     `spread` and `keep`), with random numbers of their own so the meshes don't change; `settle` moves them with
     the model. Its `.habitat` says what they are on: `"tree"`, `"conifer"`, `"bush"` or `"hedge"`. The gate
     checks them against the file.

### Wiring a new object into the game

- **Content.** An entry in a content file (`web/public/content/catalog2/<room>.json` for the catalogs): `id`,
  `name`, `model`, `footprint`, `price`, `category`, `group` (a group of that category in `base.json`
  `buyCategories`), `slots`, `description`, `interactions`, each with an `anim` (one of `base.json`
  `animations`). Copy an object like it (`bedDouble`, `sofaBed`).
- **Room kind.** Rooms are typed by their objects' interaction tags, the first matching `roomKinds` entry winning:
  anything with a `sleep` tag makes its room a bedroom; only `nap`, as on the sofa bed, leaves a living room one.
- **Opening and closing.** For something that opens and stays open (the wall bed), the interaction fields `when`
  and `leaves`, and the model's `motions.open` (below).
- **Renderer tables** (`web/src/render/shared/characters/seats.ts`), by object id: `BEDS` (from furniture.json's
  `beds`: the mattress top's height, for anything residents lie on); `BLANKET_BEDS` (sleepers get a blanket: then
  don't model a full duvet, it shows doubled).
- **Tests.** `cargo test -p sim-core --test sim shipped_content::` checks that every object's and item's model has
  its file (and its `far` file) once the manifests are stacked (a pack left out of `packs` fails it), every
  interaction has an animation, and the categories and groups exist. Changed the sim? `cargo test -p sim-core`,
  then `bun run wasm` in `web/` before testing in the browser.

## A moving part (door, lid, drawer, fold-down bed)

```rust
let door = new_parts(|| {                            // everything made in the closure
    fbox!(F, "door_fridge", 0.728, 1.146, 0.04, (0, 0.643, 0.195), M.body, bevel = 0.01);
    handle(..);
});
let door = hinged(join(&door, "door_fridge", None), F.at(0.364, 0.643, 0.195)); // origin on the hinge
settle_all();                                        // before the clips: they key the rest pose
swing!(door, "fridge_open", -102, seconds = 1.75);   // turn about its own z (axis = Axis::X for a lid)
slide!(drawer, "drawer_open", (0, -0.3, 0), seconds = 0.8); // pull out to the front
```

The clips (`artkit::motion`; offsets and axes are the kernel's, angles in degrees):

| Clip | Does | For |
|---|---|---|
| `swing!(part, clip, degrees, seconds, axis = Axis::Z, ease)` | turns from rest by `degrees`; `ease = Ease::BackOut` swings `overshoot` (4 %) past open and settles | doors (`BackOut`), lids, a bed folding down |
| `slide!(part, clip, (x, y, z), seconds, ease)` | moves from rest | drawers, a cover sliding off |
| `grow!(part, clip, seconds, axis)` | scales from how it was built (small, hidden) to full size | water, flames, washing on a line |
| `squash!(part, clip, scale, seconds, back, split)` | scales from rest to `scale` (a number or (x, y, z)); `back`: and home again, `split` of the way through | a cushion sinking, something hidden while held (0.001) |
| `spin!(part, clip, turns, seconds, axis)` | whole turns at an even speed, ending at rest | wheels, platters, fans |
| `rock!(part, clip, degrees, seconds, axis = Axis::X)` | out, back past rest and home, as a pendulum | rocking chairs, swings, the seesaw |
| `motion::scroll(part, clip, (x, y, z), seconds)` | moves by one repeat of a pattern at an even speed; the game jumps it home unseen | a treadmill's belt slats |
| `motion::turns(parts, clip, (x, y, z), seconds)` | the parts take turns moving out and back, ending at rest | a dance floor's tiles |
| `motion::path(part, clip, keys, linear)` | moves and turns from rest through keys (seconds, offset, turn in degrees; the first at 0 s is rest) | the pool rack lifted off and hung up |
| `stages!(part, clip, picked, growing, planted, seconds, sink)` | a crop's scale at each growth stage, ripe at rest | vegetables, fruit, a veggie bed |
| `wobble!(part, clip, degrees, seconds, axis, swings, delay)` | knocked out, swinging back smaller each time, home at rest | a towel on a door, a pan on its hook |
| `motion::keys(part, clip, channel, index, keys)` | keys one channel at those times, the first at 0 s at rest | a clip none of the others make |
| `motion::attach(part, parent)` | (no clip) puts a part inside another, to move with it and by its own clips | a lever on a door, a label on a record |

`ease` is an `Ease`: `Smooth` (the default), `Linear`, `Out`, `In`, `InOut`, `ExpoOut`, `BackOut` and
`BounceOut`. A use's clip plays back to close, so its curve runs the other way then. Overshoot only where there's
room past open (a door, not a lid against a wall). The first four go from rest to open: the game holds them open
and plays them back. `spin`, `rock` and `turns` end where they start, so they also loop; `scroll` ends one slat
on, so hide the part's ends under covers. Keep a spin under about a turn a second (two at most): the game blends
between samples 1/60 s apart, and the gate warns past 12° in that. A part that looks the same turned (four fan
blades) can turn by less and loop. A part easier to build open (a bed that folds down) is built open, `hinged`,
turned to rest with `turn(part, -90, Axis::X)` and swung open again by the opposite angle.

How the parts work:
- **Nodes.** Each moving part is its own node, named for what it is; the still part is one more node, joined with
  its origin at `(0, 0, 0)`. Each part costs a draw call (plus one per textured finish in it).
- **Parts inside parts.** `motion::attach` (after `settle`, before the clips) puts a part inside another: it goes
  with the parent's clips and plays its own on top, about its own origin (the retro fridge's lever on its door).
  Clips of one part play together; for a swing and a spin, give each its own node this way.
- **Clips.** A clip's first key is the rest pose, where the game draws the part closed. Turns are about the part's
  own axis: about z, negative opens a door hinged on its right; about x, negative lifts a lid's front.
- **When they play** is the model's `motions` (objects.md, "Moving parts", has every form):
  - `{"uses": {"fetch": "fridge_open"}, "hold": 3.5}`: a use, by interaction id or animation tag, plays a clip
    for `hold` seconds (absent: until the use ends); a list of clips, each `{"clip", "hold"}`, for several.
  - `{"clip": "fridge_open", "delay": 0.3}`: the clip starts 0.3 s into the use (its `hold` from then).
  - `{"clip": "swish", "delay": 1.4, "every": 3.2}`: from rest to rest every 3.2 s while the use lasts; it must
    end where it starts. Make `every` a hair under the clip's length so the rounds run on without a pause.
  - `{"clip": "turn_down_upper", "slot": 1}`: only for the resident in that slot.
  - `{"clip": "door_open", "delay": 0.3, "hold": 2.4, "out": 1.6}`: opens again for 1.6 s when the use ends (the
    phone box's door; `STEP_IN` in `web/src/render/shared/characters/actions.ts` times the steps to it).
  - `{"loops": {"relax": "rocking"}}`, `{"ride": "rocking"}`, `{"idle": "blades_turn"}`, `{"running": ..}`,
    `{"night": "close"}`, `{"clock": {"hour": .., "minute": .., "at": 610}}`, `{"growth": "grow"}`,
    `{"open": "bed_down"}`: a loop while the use lasts, the part riders move with, always near the camera (not
    on Low), while it runs on its own, from dusk to dawn, a clock's hands, a crop's stage, held open while the
    object is open (list the uses that open it in `uses` too).
  - A part the resident holds while using it (content `held`: a guitar, a barbell) is drawn in their hands, in the
    part's own frame: give it its origin where it's held from and its axes as it's held; turn it into place on the
    object with its node's rotation (`set_rotation`), not `turn`, which bakes the turn into the mesh; hide it while
    used with `squash!(part, "off_stand", 0.001, seconds = 0.2)` in `uses`.
- **Timing.** A clip starts when the use starts, once the resident has arrived, or its `delay` later. Keep a use's
  clips short, about 1 s: the gate warns of one over 3 s. Loops, `idle`, `night`, `open` and `growth` clips keep
  their own pace.
- **Checks.** The build fails if `motions` names a clip the model doesn't have. The gate fails a clip nothing
  plays, a `delay`, `hold`, `every`, `out` or `slot` that isn't one, and a loop (or `idle`, `every`, a clock
  hand) that doesn't end where it starts; one that ends a whole fraction of a turn round, or moved at an even speed,
  is a warning to check. A part a clip grows is measured grown; one flattened to nothing at rest fails if its flat
  shape shows (traps).
- **Pictures.** `--preview` draws each clip open (`<id>@<clip>.png`), `--sheet` each along its length;
  `/clips.html?keys=model.<id>` plays every clip as the game does.
- **Examples.** The template (`src/template.rs`): a lid and a drawer. `crates/art/wet/src/kitchen`: the fridge's
  doors, played by uses. `crates/art/rooms/src/living`: the wall bed, built open, folded to rest, held down while
  open.

## Writing a build

- **One scene a thread.** A build fills an empty scene and returns its parts (none: every mesh in the scene). The
  models of a family are built side by side, so a family keeps no state between them; `Build` is a function
  pointer, so a closure becomes a named function.
- **Parts.** `new_parts(|| { .. })` gives the parts made inside it, once it returns: measure them after it, not
  inside. `join(&parts, name, origin)` makes them one part, `join_all(name)` the whole scene; `hinged(obj,
  pivot)` puts a moving part's origin on its hinge; `aside(&parts, name)` keeps what a model carries out of its
  size (objects.md); `settle_all()` stands the model on the floor and centres it. Settle before the clips.
- **The same bytes on every build**, on every machine (CI checks it, `cargo art --all --check`): maths through
  `artkit::math` (`math::sin`, `cos`, `pow`, computed in software; `f64::sin` and `powf` are the platform's),
  every random number drawn in a fixed order (into a `let`, not a lazy iterator, a `zip` or `filter` that stops
  early), no `HashMap` walked (a `Vec` of pairs, a `BTreeMap`), no `sort_unstable` of ties, no time or thread in a
  number. A far version built at low detail draws the same numbers as the model, in the same order.
- **Names.** A name in use gets the lowest free number: a second `leg` is `leg.001`, and a part joined away leaves
  its name taken. The file's nodes are written by name (digits as numbers, no case), a child before its parent.

## Traps

- **Wall face.** A model built on the tile's back edge sits inside the house wall; wall faces are 7 cm in. The gate
  fails a model whose back reaches over 1 cm past the face.
- **Against a wall, on the floor.** Centred on its tile, a counter or a fridge stands 3–13 cm off the wall and off
  its content `surface`. Give its `Model` a `centre` (the back of a counter or a fridge is 0.43 m in from the
  middle of its tile); a failed size or centre check prints the measured centre to copy. No content fact says a
  thing stands against a wall, so the gate can't tell one standing off it: check by eye.
- **Thin on the floor.** A house's floor is drawn 1 cm up and hides anything lower: a mat or a belt must reach
  1.2 cm. The gate fails a floor model, or a moving part, whose top is lower (not a held `tool.*`).
- **Grown from nothing.** A part grown from 0.001 along one axis keeps its other two, so at rest it lies flat where
  its origin is, and shows there (a dartboard's flights as crosses on its face). Put its origin inside something
  opaque. The gate fails a flat shape 3 cm across or more that shows.
- **Settle first.** `settle_all()` before `swing!`/`slide!`: clips key the rest pose where it is. The kernel
  refuses after.
- **Size check.** It counts everything at rest: knobs, handles, a folded bed's foot rail. Set the size from the
  measured line once the model looks right; an off-centre model needs its `centre` or the size check fails.
- **Lopsided turning parts.** `settle` centres the model's box, which moves a part that goes round off the middle
  when it reaches farther one way (five fan blades: 3.3 cm), and it then sweeps past its tile. Build it with its axis
  on the middle, `settle!(centre = false)`, and give the `Model` the box's middle as its `centre`
  (crates/art/rooms/src/lighting `ceiling_fan`). The gate fails a spun part whose circle reaches over 1 cm past the
  footprint, indoors.
- **Clicking.** An object is clicked by its drawn outline at rest, never past its tiles; one held open by its whole
  tiles. The contact shadow is the model's own shape at rest, seen from above.
- **Doubled covers.** A per-sleeper blanket (`BLANKET_BEDS`) and a modelled duvet show double.
- **Room kind.** A `sleep` interaction turns a living room into a bedroom.
- **Mirrors past the nearest.** Only the nearest mirror on screen reflects (two on High): map mirror glass to
  `gloss`, never see-through `glass`, or it shows what is behind it.
- **Curves that overshoot.** `sweep!` (and `kit::tube!`) with `resolution` over 1 curves through the points
  (Catmull-Rom), which bulges past them where a long straight meets a short leg. For bent tube and corners, round
  the corners with `kit::fillet!` and sweep at `resolution = 1`.
- **Shading by corners.** The baked shading is per vertex, so a face is as dark as its corners: a big flat face
  whose corners sit in a crease (a recessed panel, glass in a rim) goes dark all over. Give a face that meets a
  crease an edge band (`kit::shaker!` does).
- **Smooth, sharp and bevelled.** Smooth parts keep edges over 40° (`shapes::SHARP`) sharp, so a cylinder's cap stays
  flat; round things with few sides stay round (`shapes::round_angle`); a lathe keeps only turns over 70° sharp;
  spheres, rings and boulders are smooth all over. A `bevel` is smooth with hardened normals: the faces it joins
  stay flat, the edge rounds. `shapes::shade` and `bevel::bevel_edges` do the same to a mesh made by hand.
- **Boxes come chamfered.** A `cube!` or `fbox!` that names no `bevel` takes a 4 mm chamfer (`shapes::AUTO_BEVEL`)
  where the gate's `edges` would find its edges hard (every side 12 mm or more, the longest 5 cm or more), none in a
  far version. `bevel = 0` keeps one sharp: a plate set in a frame, a liner whose edges hide inside something.
- **`up` is the kernel's.** `fsweep!` maps the points to game axes but passes `up` (which way a profile's first
  side faces) as it is, in the kernel's axes: `up = (0, 1, 0)` on a path along game x flips a profile down.
- **The bevel is lazy.** `bevel = ..` only asks: the part is rounded when it is joined or written. Until then its
  mesh is the unbevelled one; `measure`, `settle` and the size check count the bevel.
- **Whole zeros.** `F.at` negates x and depth, and `-0` is `0` where `-0.0` is `-0.0`: a part's place keeps the
  sign, and the file keeps it too. Write whole numbers whole (`(0, 0.735, 0)`).
- **Turned by a quaternion.** A `rod!` is, and so is what is joined onto one: an Euler turn does nothing to it until
  its mode is set. `swing!`, `spin!`, `rock!`, `wobble!` and `path` set it themselves.
- **Plain leaves.** A plant's leaves on a plain finish (`plain_leaves`) no longer sway, count as edges in the
  gate, and are found by `cargo review sizes` by their names (`leaf`, `stem`), not their finish: name them so.
- **Doubled faces go when written.** The writer drops a face on the corners of an earlier one, after the shading:
  the file can have fewer triangles than the build's line says.
